## 快速开始

### 配置文件位置与用途

ZGR 涉及多个 `game_property` 配置文件，按优先级从高到低排列：

| # | 路径 | 生效场景 | 用途                                                             |
|---|------|---------|----------------------------------------------------------------|
| 1 | `<世界存档>/serverconfig/zgr_game_property.json` | **服务端运行时** | 每个世界独立的配置。由 OP 在游戏内编辑后上传保存                                     |
| 2 | `config/zombiegamereborn/default_game_property.json` | **新世界首次启动** | 客户端全局默认模板。当 `serverconfig` 中不存在配置文件时，模组读取此文件作为基础配置写入世界存档       |
| 3 | `config/zombiegamereborn/game_properties/*.json` | **导入/导出 GUI** | 用户通过游戏内预设管理器保存/加载的本地预设文件，与服务器配置无关，仅在编辑界面中用于快速切换配置方案            |
| 4 | (模组 jar 内置) `/data/.../initial_default.json` | **导入/导出 GUI** | 模组出厂自带的初始预设，在预设管理器中显示为 **[预设]**。无法重命名或删除，作为配置参考基准              |
| 5 | (代码硬编码) `GamePropertyPresentUtils` | **导入/导出 GUI** | 三个硬编码内置预设：全局默认值（同上）、初始默认值（出厂）、禁用（不启用ZGR）。始终在预设列表顶部显示为 **[预设]** |

> 配置生效链路：`serverconfig/zgr_game_property.json` → 客户端 `default_game_property.json` → `GameProperty.empty()`（代码兜底）

### 最小可用配置

```json
{
  "stage_properties": [
    {
      "day": 1.0,
      "zombie_property": {},
      "zombie_spawn_chooser": {
        "zombie_types": [
          {
            "spawn_type": "normal",
            "chance": 1.0,
            "zombie_type": "zombiegamereborn:vanilla"
          },
          {
            "spawn_type": "drowned",
            "chance": 1.0,
            "zombie_type": "zombiegamereborn:vanilla"
          },
          {
            "spawn_type": "blood_moon",
            "chance": 1.0,
            "zombie_type": "zombiegamereborn:vanilla"
          }
        ]
      },
      "replace_chance": 0.0,
      "remove_chance": 0.0,
      "blood_moon_chance": 0.0,
      "zombie_count_modify": 1.0,
      "holy_cleansing": false
    }
  ],
  "can_zombie_break_block": true,
  "can_zombie_place_block": true,
  "can_piglin_infection": true,
  "mob_replacement": { "mobs": [] },
  "keep_mob_loot_table": true,
  "max_empowered_builder_count": 100,
  "max_empowered_miner_count": 100
}
```

### ⚠️ 重要提示

| 参数 | 说明 | 性能影响            |
|------|------|-----------------|
| `max_empowered_builder_count` | 最大激活建造者数量 | 默认 100 已流畅      |
| `max_empowered_miner_count` | 最大激活挖掘者数量 | 同上              |
| `disable_turtle_egg_seeking` | 禁用僵尸寻找海龟蛋 | 建议开启 |

## 🔴 配置警示与最佳实践

### 阶段设计

- **建议 10 阶段均匀分割 100 天**：每 10 天一个阶段，day 依次设为 1、11、21、31…91，精确映射 100 天的完整难度曲线。
- **三个 spawn_type 都必须有僵尸占位**：`normal`、`drowned`、`blood_moon` 池各至少一条有效条目，否则该场景降级生成 `dummy`（无 AI 僵尸）。
- **移除概率 `remove_chance` 随阶段动态递增**：从 0% 逐渐增加到 80%，不要设 100%（保留部分非敌对生物维持世界生态）。
- **替换概率 `replace_chance` 建议全程 100%**：确保所有标记为 replace 的生物必定替换为僵尸。

### 僵尸属性安全阈值

- **`movement_speed_modify` 不要超过 1.4**：超过 1.4 会导致僵尸寻路漂移、卡地形。
- **不建议修改 `max_health`**：改 `armor`（0~30）和 `armor_toughness`（0~20）更安全。
- **不要动 `baby_probability`**：幼体移速过快导致寻路失效，保持 0 或默认 0.05。

### 僵尸类型投放时机

- **弓箭手、弩手、持盾者是超后期单位**：建议第 70 天后的阶段才引入，总权重占比不超过 5%。
- **Builder/Miner 破坏性极强**：建议只在血月池和后期阶段（60 天以后）出现，用 `max_empowered_*_count` 严格控制数量。

### mob_replacement 使用原则

- **直接使用默认完整列表，不要精简**：默认列表已将所有非僵尸生物替换/移除，删除条目会导致非僵尸生物重新出现，破坏末日氛围。
- **`mob_replacement` 中的 replace 条目设为 `action: "replace"` 后，配合 `replace_chance: 1.0` 即可实现 100% 僵尸替换。

## 顶层配置结构

### `GameProperty` 字段一览

```json
{
  "stage_properties": [...],           // 阶段列表（核心）
  "can_zombie_break_block": true,      // 全局：僵尸能否破坏方块
  "can_zombie_place_block": true,      // 全局：僵尸能否放置方块
  "can_piglin_infection": true,        // 僵尸感染猪灵（→僵尸猪灵）和疣猪（→僵尸疣猪）
  "mob_replacement": { ... },          // 生物替换规则
  "keep_mob_loot_table": true,         // true=替换后保留原生物战利品表；false=替换后使用僵尸默认战利品表（腐肉等）
  "max_empowered_builder_count": 100,  // 建造者数量上限
  "max_empowered_miner_count": 100,    // 挖掘者数量上限
  "disable_turtle_egg_seeking": false  // 禁用寻蛋（优化性能）
}
```

## 阶段系统（Stage System）

### 设计理念

阶段系统允许你根据游戏天数**动态调整僵尸的强度、行为和生成逻辑**。多个阶段构成一条时间线，游戏根据当前天数自动匹配对应的阶段。

### 阶段匹配规则

```text
假设定义了：
  Stage A: day=1
  Stage B: day=5
  Stage C: day=10

Day 1.0 ~ Day 4.99 → 匹配 Stage A
Day 5.0 ~ Day 9.99 → 匹配 Stage B
Day 10.0 起        → 匹配 Stage C
```

> `day` 阶段的生效区间为：`当前天数 ≥ 本阶段 day，且 < 下一阶段 day`（若为最后一个阶段则 `≥ 本阶段 day` 一直生效）

> ⚠️ **注意**：`<=` 是包含等于的，所以第 5 天当天就会切换到 Stage B。

### `StageProperty` 结构

```json
{
  "day": 1.0,                    // 起始天数
  "zombie_property": { ... },    // 僵尸属性
  "zombie_spawn_chooser": { ... }, // 生成选择器
  "replace_chance": 0.0,         // 替换概率（非僵尸→僵尸）
  "remove_chance": 0.0,          // 移除概率（取消生成）
  "blood_moon_chance": 0.0,      // 血月触发概率
  "zombie_count_modify": 1.0,    // 僵尸数量修正比
  "holy_cleansing": false        // 圣火净化
}
```

### 字段详解

| 字段 | 类型 | 取值范围 | 说明 |
|------|------|---------|------|
| `day` | double | [1.0, ∞) | 阶段生效的起始天数 |
| `zombie_property` | object | — | 该阶段的僵尸属性配置 |
| `zombie_spawn_chooser` | object | — | 僵尸类型选择器 |
| `replace_chance` | double | [0.0, 1.0] | 非僵尸生物被替换为僵尸的概率（仅对未在 `mob_replacement` 中锁定的生物生效） |
| `remove_chance` | double | [0.0, 1.0] | 非僵尸生物被移除的概率（同上，对被 `mob_replacement` 锁定为 remove/replace 的生物**不生效**） |
| `blood_moon_chance` | double | [0.0, 1.0] | 血月触发概率 |
| `zombie_count_modify` | double | [0.0, ∞) | 僵尸生成数量修正比 |
| `holy_cleansing` | boolean | true/false | `true` 时所有僵尸被点燃且**不会生成新僵尸**。⚠️ **一旦开启当前阶段将不再刷新任何僵尸，且不会自动恢复，请勿在常规游戏中使用** |

## 僵尸生成选择器

### 结构

```json
{
  "zombie_spawn_chooser": {
    "zombie_types": [
      {
        "spawn_type": "normal",        // normal / drowned / blood_moon
        "chance": 1.0,                 // 权重
        "zombie_type": "zombiegamereborn:vanilla"
      }
    ]
  }
}
```

### 三种生成场景

| `spawn_type` | 触发时机 | 说明 |
| --- | --- | --- |
| `normal` | 普通自然生成 | 僵尸、尸壳、僵尸村民等 |
| `drowned` | 溺尸生成 | 建议填入`vanilla`，因为暂未制作溺尸相关的AI |
| `blood_moon` | 血月期间 | 覆盖上述`normal`普通生成，营造尸潮 |

### 权重抽选机制

  - 每种 `spawn_type` 拥有**独立的权重池**，所有权重和为任意值，按加权随机抽选（`chance=1.0+1.0` 各 50%，`chance=1.0+3.0` 为 25%/75%）
  - 血月期间：**完全不读取 `normal` 数组**，仅从 `blood_moon` 池中抽取
  - 如果 `blood_moon` 池为空，此时会降级生成 `dummy` 僵尸（无 AI，站着不动）

## 生物替换系统

### 结构

```json
{
  "mob_replacement": {
    "mobs": [
      { "mob_id": "minecraft:cow", "action": "remove" },
      { "mob_id": "minecraft:skeleton", "action": "replace" }
    ]
  }
}
```

### `action` 说明

| action | 效果 |
| --- | --- |
| `remove` | 该生物不会自然生成 |
| `replace` | 该生物被替换为僵尸（按生物群系映射变种） |

> `mob_replacement` 使用 `HashMap` 存储，同一 `mob_id` 仅最后一条 `action` 生效。多人协作编辑时注意避免重复。

## 僵尸类型大全

ZGR 提供了 **10 种不同的僵尸类型**，每种都有独特的行为逻辑。

### 类型总览

| 注册 ID | 语言键 | 近战 | 破方块 | 放方块 | 核心特长 |
|---------|--------|:----:|:------:|:------:|----------|
| `zombiegamereborn:dummy` | Dummy | ❌ | ❌ | ❌ | 完全无 AI，站着不动 |
| `zombiegamereborn:vanilla` | Vanilla Zombie | ✅ | ❌ | ❌ | 纯原版僵尸行为 |
| `zombiegamereborn:enhanced_vanilla` | Enhanced Vanilla | ✅ | ❌ | ❌ | 近战 AI 增强 |
| `zombiegamereborn:builder` | Builder | ✅ | ✅ | ✅ | 破墙+铺路+搭桥 |
| `zombiegamereborn:miner` | Miner | ✅ | ✅ | ❌ | 智能破坏方块 |
| `zombiegamereborn:bow_attacker` | Bow Attacker | ❌ | ❌ | ❌ | 弓箭手 |
| `zombiegamereborn:crossbow_attacker` | Crossbow Attacker | ❌ | ❌ | ❌ | 弩手 |
| `zombiegamereborn:shield_user` | Shield User | ✅ | ❌ | ❌ | 持盾格挡+盾击 |
| `zombiegamereborn:musket_mod_gunner` | Musket Gunner | ❌ | ❌ | ❌ | 火枪手（需火枪模组） |
| `zombiegamereborn:zombie_guard_villager` | Zombified Guard Villager | ❌ | ❌ | ❌ | 感染警卫（全能武器） |

### 详细说明

> ⚠️ **模组依赖类型**：`musket_mod_gunner` 需要 Musket Mod，`zombie_guard_villager` 需要 Guard Villagers。未安装对应模组时，该类型的安全降级为近战，不会崩溃。

#### 1. `dummy` — 无 AI 僵尸

清除所有目标和行为 Goal，完全不会移动、攻击、索敌。

---

#### 2. `vanilla` — 原版僵尸

直接继承基类，仅比原版多出装备和附魔增强功能。

---

#### 3. `enhanced_vanilla` — 增强原版僵尸

将原版的 `ZombieAttackGoal` 替换为 `EnhancedZombieAttackGoal`（更算力节约的智能的近战 AI）。

---

#### 4. `builder` — 建造者僵尸 ⭐

| 能力 | 实现                                  |
|------|-------------------------------------|
| 破坏方块 | `ZombieBreakBlockGoal` — 自动破坏阻挡路径的方块 |
| 放置方块 | `ZombiePlaceBlockGoal` — 手持副手方块时自动放置 |
| 清头顶 | `ClearHeadBlockGoal` — 清除窒息的方块      |
| 水上铺路 | `ZombieWaterBridgeBuildGoal` — 在水面搭路 |
| 近战攻击 | `ZombieMeleeAndPathBuildGoal` — 边打边铺路 |

**装备特点**：
- 40% 概率持镐，60% 概率持常规武器
- 副手必定持一个路径方块（根据生物群系自动选择）

**激活机制**：
- 初始状态 `isEmpowered = false`，不会执行核心建造 AI
- 通过配额系统竞争激活名额（由 `max_empowered_builder_count` 控制）

---

#### 5. `miner` — 挖掘者僵尸 ⭐

| 能力 | 实现 |
|------|------|
| 破坏方块 | `ZombieSmartBreakAttackGoal` — **智能破坏**，优先破坏通向玩家方向的方块 |
| 放置方块 | ❌ |

与 Builder 配额系统相同，由 `max_empowered_miner_count` 控制激活数量。

---

#### 6. `bow_attacker` — 弓箭手僵尸

- 主手持弓
- 使用 `ZombieBowAttackGoal` 远程攻击
- 有近战备用 Goal

---

#### 7. `crossbow_attacker` — 弩手僵尸

- 主手持弩
- 使用 `ZombieCrossbowAttackGoal` 远程攻击
- 僵尸猪灵如果手持弩，会自动覆盖为此类型

---

#### 8. `shield_user` — 持盾者僵尸

- 副手持盾
- `ZombieShieldGoal`（举盾格挡）+ `ZombieShieldAttackGoal`（盾击）
- 格挡正面攻击时不受伤

---

#### 9. `musket_mod_gunner` — 火枪手僵尸

- 需要安装 **Musket Mod** 模组
- 使用火枪远程射击
- 伤害由 `musket_mod_gun_damage_modify` 控制
- 未安装模组时退化为近战

---

#### 10. `zombie_guard_villager` — 僵尸警卫村民 ⭐

**需要安装 Guard Villagers 模组。**

| 模式 | 条件 | 行为 |
|------|------|------|
| **全能模式** | `canZombieGuardContinueUseWeapons = true` | 同时拥有弓箭+弩+火枪+盾牌四种武器能力 |
| **近战模式** | `canZombieGuardContinueUseWeapons = false` | 仅增强近战 |

这是**唯一同时拥有四种武器能力的类型**。

### 表三：附魔概率（`equipment_enchantment_factor`）

**基础公式：**
```
武器附魔概率 = 0.25 × difficulty × factor
盔甲附魔概率 = 0.50 × difficulty × factor（每件独立判定）
附魔等级 = 5 + difficulty × random.nextInt(18)，取整（范围随难度线性变化）
```

> `difficulty` 由 `calculateDifficulty()` 计算，简易=0.28、普通=0.51、困难=0.70。

## 常见问题（Q&A）

### Q1：阶段数组是否必须按 day 从小到大排序？

**A**：不必须。代码内部会自动按 day 升序排序，无论 JSON 中顺序如何，运行时行为一致。

---

### Q2：`zombie_count_modify` 填 0 或负数会怎样？

**A**：填 0 时僵尸不自然生成。负数同理（计算结果 clamp 到 0）。建议范围 `0.0 ~ 10.0`。

---

### Q3：同一 spawn_type 下多个 type 的 chance 是权重还是概率？

**A**：权重比值，按加权随机抽选。`1.0+1.0` → 各 50%；`1.0+3.0` → 25%/75%。不同 spawn_type 池互不干扰。

---

### Q4：blood_moon 池为空时血月会发生什么？

**A**：降级生成 `dummy` 僵尸（无 AI）。不会崩溃。

---

### Q5：`remove_chance` 和 `replace_chance` 会同时作用于同一生物吗？

**A**：不会。`mob_replacement` 中每只生物预先指定了 `remove` 或 `replace`，两种概率分别作用于各自的生物集合，互不交叉。

---

### Q6：`mob_replacement` 中出现重复 mob_id 会怎样？

**A**：最后一条覆盖前面的。`HashMap` 行为。

---

### Q7：模组生物填错 mob_id 会崩溃吗？

**A**：不会。错误 ID 在运行时不会匹配任何真实生物，静默跳过。

---

### Q8：`holy_cleansing` 是永久生效吗？

**A**：是阶段级别的实时开关。游戏每 20 tick 读取当前阶段配置：

- 当前阶段 `holy_cleansing: true` → 所有僵尸被点燃，**不会生成新僵尸**
- 切换到 `holy_cleansing: false` 的阶段 → 僵尸不再被点燃，恢复正常生成

> ⚠️ **警告：一旦 `holy_cleansing: true` 的 tick 被执行，当前阶段将彻底停止所有僵尸生成。这不是存档级开关，切换阶段后可以恢复，但在此期间玩家将无怪可打。不要在日常配置中使用此字段，除非你有明确的设计意图。**

---

### Q9：JSON 格式写错（少逗号、缺引号）会崩溃吗？

**A**：不会崩溃进不了服，但你的自定义配置会丢失。模组输出错误日志后使用全默认配置继续运行。

---

### Q10：删除顶层字段（如 `max_empowered_builder_count`）会怎样？

**A**：安全删除。缺失字段会自动使用代码内的默认值。

---

### Q11：阶段内 `max_empowered_zombie_*_count` 和顶层的区别？

**A**：阶段内的两个字段是预留字段，**当前版本未接入配额系统**。实际配额仅由顶层 `GameProperty` 的两个字段控制。

---

### Q12：drowned 池能否填非 vanilla 类型？

**A**：可以但不推荐。Builder 的`ZombieWaterBridgeBuildGoal`会持续尝试在脚下放置方块，水下放置的方块被水流冲毁，导致 AI 无限循环"寻路→放方块→冲毁→重试"，每分钟产生大量无效 CPU 计算。建议只放 `vanilla`。
